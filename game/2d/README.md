# 2.5D 美術與戰鬥試作

入口：<https://tools.investmquest.com/game/2d/?view=warrior>。首頁主按鈕通往第三人稱試驗版，角落保留斜俯視版連結，旁邊另有舊版 3D 四關入口。

這是 Rumi 單角色、首爾夜市單場戰鬥的可玩版本，供檢查新的插畫方向與戰鬥表現。原 3D 四關戰役保持原樣；此版本尚未移植 Mira、Zoey、換武器、跳躍、對話和四關目標。首領暫時使用放大的妖將圖集，並非已完成獨立首領美術。

`?view=warrior` 是背後追蹤角色的第三人稱視角試驗，首頁主按鈕導向這個版本；不帶此參數則保留斜俯視版以便比較。兩者共用戰鬥核心，但第三人稱版有獨立的敵群密度、波次長度、攻擊速度和近距離瞄準。Rumi 現有八個背面關鍵姿勢，三段輕斬會交替左右橫斬與下劈收尾，重擊也依動作時間切換起手、命中和收刀姿勢；敵人準備攻擊時，頭上會顯示倒數警示。這仍是固定方向的 2.5D 假透視，並非可自由旋轉的真 3D 世界；角色只能左右鏡像，還缺少其他方位的完整動作圖。

## 已接入的玩法

- 2.5D 呈現：保持繪製戰場的地面座標，角色／接地陰影／血條隨遠近縮放；角色繪於敵人前方，減少圍攻時完全被遮住。戰場背景保持原尺寸，前景人物平滑跟隨鏡頭，沒有進場固定放大。桌面比例不合時，用深色漸層襯托戰場。這是插畫搭配景深與前後層次的呈現，不是可自由環繞的 3D 場景或角色模型。
- 暫停選單可以關閉鏡頭跟隨；系統「減少動態效果」開啟時預設關閉跟隨。手機操作鍵與 HUD 不隨鏡頭移動。

- WASD／方向鍵移動，J 三段普攻，K 重擊；普攻中接 K 可派生範圍更大的重擊。
- Shift 閃避，E 消耗全滿靈力施放範圍絕招，P 暫停。
- 手機橫向左搖桿、右側四個動作鍵。直向暫停，轉回橫向重新取得控制區位置並清空舊輸入。
- 斜俯視版為三波各 20 次擊倒、最多 14 名敵人。第三人稱版縮短為兩波各 10 次擊倒、最多 8 名敵人；敵群在前方散開、每次最多兩名敵人貼近攻擊，角色出刀時可以持續前進。清完殘餘敵人後出現魂門守將；精英有獨立血條，攻擊先顯示警示圈。
- 0.18 秒攻擊緩衝、閃避冷卻、命中停頓、重擊推退、波次回復少量體力、失敗重試。
- 首頁及暫停畫面可近看實際遊戲角色素材，切換站姿、奔跑、連斬與重擊。全程靜音。
- 整個遊戲介面與一般按鈕使用 `touch-action: manipulation`，戰鬥畫布／搖桿／動作鍵保留 `none`；另限制遊戲區域內的 `dblclick` 預設行為與相近位置的第二次 `touchend`，防止連點意外放大。第一下、不同位置、雙指手勢不攔截。手勢語意依 [MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action)。

## 效能設計

Canvas 2D 與預繪場景，不載入 Three.js、GLB、動態燈光或後處理。斜俯視版保留無損 WebP；第三人稱版改用高品質 WebP，透明度逐一比對完全相同，可見色彩的 PSNR 最低 37 dB，並已目視比較整張場景與角色圖。Rumi 仍不是八方向獨立繪製。

畫面最多提交 60 次／秒，背後分頁、手動暫停、手機直向與結算停止動畫排程；角色近看的靜止站姿也停止排程。角色近看只載入角色圖；開始戰鬥才載入敵人與場景，已下載圖片共享。載入顯示完成數，失敗或 45 秒逾時可重試；敵人與短暫特效有上限。Canvas 使用裝置像素比，最高 2，沒有依幀率動態模糊畫面的機制。

第三人稱模式的四張執行圖片合計 2,194,386 bytes，約為前一版下載量的一半；新動作圖集只有 281,382 bytes、解碼後約 7.5 MiB。背景仍是一張預繪圖，角色仍是透明圖集，每幀只做數學投影及 Canvas 2D 繪製，沒有新增 WebGL 或 3D 模型下載。

圖片尺寸、來源及生成提示見 [assets/README.md](assets/README.md)。`?debug=1` 可顯示取樣幀率、當次 JS 更新及繪圖提交耗時、敵人數與座標；它不量測完整 GPU／合成耗時，也不是正式效能評測。

## 2026-09-24 驗證

- `node --experimental-default-type=module --loader ./game/tests/three-loader.mjs --test game/tests/*.test.mjs`：95 項通過，含 14 項 2D 戰鬥測試、6 項載入／重試測試、6 項景深／鏡頭／手勢測試、2 項第三人稱投影與背景邊界測試。
- `node game/scripts/prepare_2d_assets.mjs --check`：三組 PNG／無損 WebP 的尺寸、透明度與可見像素一致（離線檢查需 sharp）。
- 三個固定種子的完整戰鬥使用公開輸入介面模擬通關：三波、清場、首領、勝利皆可到達，無直接修改生命或波次。這驗證流程可完成，不代表難度平衡已完成。
- Chrome 獨立視窗實際靜音載入、移動／攻擊、群體擊倒、失敗結算；短測 14 名敵人時頁面取樣約 60 fps，未發生當機。這不是所有硬體的幀率保證，也不表示舊 3D Chrome 當機根因已消除。
- 內建瀏覽器 667×375 橫向：按鍵、搖桿移動、重擊；375×667 直向：暫停提示、生命值保持不變；切回橫向恢復。角色近看及尺寸切換已目視檢查，控制台無警告／錯誤。
- 尚未在實體 iPhone／Android 上驗證多點觸控、發熱與長時間遊玩；目前手機結果是視窗尺寸與指標操作檢查。
- 2.5D 更新在 667×375 預覽驗證：暫停選單與鏡頭開關可操作；連點角色動作鍵與畫布後視窗縮放值維持 1、寬度維持 667，控制台無錯誤。這是滑鼠指標雙擊檢查，不能代替實體 iOS 的觸控連點測試。
- 第二次修正：移除進入戰鬥時的 1.1 倍固定鏡頭縮放；首頁新版入口移至主按鈕；手機 667×375 預覽中戰場與觸控鍵均可見，重複點擊攻擊後視窗縮放值仍為 1。這仍不等於實機 Safari 觸控驗證。
- 第三人稱試驗：在內建瀏覽器桌面和 667×375 手機橫向預覽目視檢查背面角色、前後敵群、攻擊與操作鍵；375×667 轉向提示正常，回橫向可重新取得操作。短測 14 名敵人時頁面取樣約 56–59 fps，當次 JS 更新及畫布提交約 0.1–0.5 ms，控制台無警告／錯誤。尚未在實體 Chrome／手機上測到 GPU 合成耗時、發熱或長時間穩定性。
- 揮刀修正：逐格檢查新背面動作，在內建瀏覽器桌面和 667×375 橫向預覽確認攻擊鍵能擊倒敵人、搖桿能移動；99 項自動測試通過，涵蓋揮刀動作順序、近距離瞄準、出刀位移、敵群隊形、第三人稱完整戰鬥及原版相容。這仍不是實體手機、Chrome 長時間遊玩的驗收。
- 載入優化：`python3 game/scripts/optimize_warrior_runtime.py` 產出三張第三人稱專用 WebP，執行檢查每個透明度值不變、可見色彩 PSNR 至少 37 dB；場景圖由 2,312,922 bytes 降至 847,896 bytes。封面和戰鬥共用同一張壓縮場景圖，避免開啟頁面先下載大圖。
